> 本文定义 M1 的**可交付物、验收标准与退出条件**，用于判断 M1 是否完成、能否进入 M2。

## 1. 可交付物

| # | 交付物 | 说明 |
| --- | --- | --- |
| D1 | 可本地运行的服务 | FastAPI 服务 + Docker Compose 一键启动（ASR/LLM 走云 API） |
| D2 | 完整闭环后端 | `ingestion / audio / asr / summary / render / orchestrator / storage` 模块 + 任务状态机 |
| D3 | 极简前端 | 上传页 + 进度展示 + 结果下载 |
| D4 | 单元测试套件 | 覆盖率 ≥ 70% |

## 2. 验收标准

| # | 标准 | 判据 | 数据来源 |
| --- | --- | --- | --- |
| V1 | 自助闭环 | 无技术背景用户可自助完成「上传 → 得到纪要」 | TG-6 端到端 |
| V2 | FR-01~07 全覆盖 | 全部功能需求实现并通过测试 | TG-2~6 |
| V3 | 测试覆盖率 | 单元测试覆盖率 ≥ 70% | TG-7 收口 |
| V4 | 上传校验 | 格式白名单 / 大小 / 时长（≤2h）校验生效 | TG-2 |
| V5 | 状态机 | pending → running → succeeded/failed 正确流转、可持久化 | TG-3 |
| V6 | 异步执行 | 上传后立即返回 task id，后台完成全链路，进度可查询 | TG-4 |
| V7 | 导出下载 | 完成后可下载 Markdown 纪要 + 转写文本 | TG-5 |
| V8 | 错误处理 | 故障被捕获、重试并最终标记 failed，日志可定位 | TG-7 |

## 3. 退出条件（进入 M2 的门槛）

- ✅ 端到端流程稳定运行，核心功能无阻断性 Bug。
- ✅ FR-01~07 全部实现并通过测试。
- ✅ 单元测试覆盖率 ≥ 70%。
- ✅ 无技术背景用户可自助完成「上传 → 得到纪要」（以真实样例音频验证）。

## 5. 判定规则

- FR-01~07 全部实现、测试通过、覆盖率 ≥ 70%、端到端无阻断性 Bug → M1 通过。
- 任一 FR 未实现或测试失败 → 回到对应任务组补齐。
- 端到端出现阻断性 Bug → 定位到具体任务组修复后回归，直至稳定。
- 若云 API 密钥不可用导致端到端无法验证，明确记录阻塞原因，优先用 M0 的离线兜底（faster-whisper / extractive）跑通链路以验证服务与前端闭环。
