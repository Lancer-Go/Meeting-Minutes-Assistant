> 本文说明 M0 的**范围、已定决策与上下文**，作为 plan.md 的依据与 validation.md 的对照。

## 1. 目标（一句话）

用一段真实会议录音跑通「音频 → 转写 → 纪要」最小闭环，用实测数据锁定云 ASR 厂商与 LLM 选型，验证可行性与成本。

## 2. 范围

### 范围内 (In Scope)
- 输入一段 **≥ 10 分钟**真实会议音频（中文为主，英文术语混用）。
- FFmpeg 抽取并标准化音轨（16kHz 单声道 WAV）。
- 云 ASR 转写为带时间戳文本（对比 1–2 家厂商）。
- 调用 LLM 输出结构化 Markdown 纪要。
- 记录**耗时 / 成本 / 转写字符数**三组实测数据。
- 输出《选型决策记录》。

### 范围外 (Out of Scope) — M0
- ❌ 服务化（不建 Web、不建队列、不做上传界面）。
- ❌ 说话人分离 / 角色标注（M2）。
- ❌ 行动项结构化抽取评测（M2）。
- ❌ 多模板渲染、编辑、检索（M2）。
- ❌ 生产化部署 / 可观测 / 合规（M3）。
- ❌ 多模型热切换 / RAG / 实时转写（M4）。

## 3. 关键决策（沿用 mission.md §8，逐条映射到 M0 影响）

| --- | --- | --- | --- |

## 4. 技术选型（沿用 tech-stack.md A5，待 M0 锁定）

| 决策点 | 已定方向 | M0 待锁定 |
| --- | --- | --- |
| ASR 主方案 | ✅ 云 API | 具体厂商（阿里云 / 讯飞 / 腾讯云），依据中文准确率 / 成本 / 说话人分离 |
| LLM 主方案 | ✅ 性价比高 | 具体型号（DeepSeek / Qwen），依据纪要质量 / 成本 |

## 5. 约束与假设

- 运行环境：Python 3.11 + FFmpeg + `venv` 隔离；ASR/LLM 走云 API。
- 数据隐私：首期接受云 API 处理（数据出域），本地化部署留作后期选项。
- 形态：单脚本 `pipeline.py` 串联，**暂不做服务化**。
- 长文本：超上下文时用 Map-Reduce 分块总结（应对 mission.md §7「长会议超上下文」风险）。

## 6. 上下文（链路与模块）

M0 验证的是 tech-stack.md B2 中**处理流水线**的最小闭环，对应模块：

```
audio（FFmpeg 抽音轨） → asr（云 ASR 转写） → summarize（LLM 纪要）
```

- 这三个模块在 M1 会被重构为 `ingestion / audio / asr / summary / render` 可复用模块。
- M0 不涉及 `ingestion`（上传）、`extractor`（行动项）、`render`（模板化）、`orchestrator`（队列）、`storage`（持久化）。
